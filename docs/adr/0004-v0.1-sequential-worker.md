# ADR 0004: Limit v0.1 to one sequential worker

- Status: Superseded by ADRs 0005 and 0006 for v0.2
- Date: 2026-10-04

## Context

Leases, heartbeat, fencing, and abandoned-job recovery require a coherent
failure model and additional schema. Adding them while establishing the basic
repository and API would make the first release harder to review and test.

## Decision

v0.1 runs at most one active worker process per deployment and executes one job
at a time. Handler execution and shutdown drain are bounded. The only built-in
handler is `demo.echo`; arbitrary user code and command execution are forbidden.

The worker does not recover a job left `running` by a hard process crash.
Bounded concurrent workers, leases, fencing tokens, heartbeat, and abandoned
job recovery are v0.2 work and will use a new migration.

## Consequences

- v0.1 demonstrates durability and transactional claiming, not distributed
  execution.
- Graceful shutdown can finalize the current attempt when dependencies remain
  available.
- A hard crash can strand a running job until manual intervention or v0.2.
