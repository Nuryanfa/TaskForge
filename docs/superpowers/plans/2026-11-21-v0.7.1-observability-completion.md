# TaskForge v0.7.1 Observability Completion Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Finish every item v0.7.0 deferred (API-availability SLO, fan-in span links, workflow loadgen, dashboard polish, and the recorded v0.7 minors) plus repository hygiene, as PR #1 of the v0.7.1 → v0.8 completion.

**Architecture:** The API-availability SLI is derived from the existing `taskforge_http_requests_total{route,code}` counter, after the HTTP middleware is made to count panics as 5xx. Fan-in links are persisted, not inferred: each succeeded step stores its attempt's traceparent (migration 8), and a fan-in dispatch copies the non-triggering dependencies' contexts into `jobs.trace_links`, which `StartAttempt` turns into OpenTelemetry span links. Everything else is small, test-first fixes.

**Tech Stack:** Go 1.25, pgx v5, goose, OpenTelemetry Go v1.46.0, client_golang v1.24.0, Prometheus v3.5.0 (`promtool`), Grafana 12.1.0 (generated dashboard), Jaeger 1.71.0, Docker Compose.

**Spec:** `docs/superpowers/specs/2026-11-08-v0.7-observability-design.md` (decision 12 deferrals; SLO targets at line 418; fan-in rule at line 144), plus the owner decisions of 2026-11-21:

- Loadgen modes `workflow` and `workflow:fail`. Loadgen and telemetry unit tests must not need loopback sockets.

## Global Constraints

- Module `github.com/Nuryanfa/TaskForge`, `go 1.25.0`; do not bump; no new dependencies.
- `gofmt -l .` empty, `go vet ./...` clean, `go mod verify` clean before every commit.
- Metric labels stay bounded: no job, workflow, step, or trace IDs in labels.
- No payload, result, idempotency key, execution key, or DSN in logs, labels, span attributes, or responses.
- Every SLO alert has a firing case and a silent case in `deployments/prometheus/tests/slo_test.yml`, including a below-minimum-volume case. Every threshold and volume gate is mutation-checked: loosening it makes the suite fail.
- SLO windows: 28 days. Burn rates: 14.4× over 1h and 5m (`for: 2m`, `severity: page`); 6× over 6h and 30m (`for: 15m`, `severity: ticket`). Minimum volume: `taskforge:slo_min_events_per_hour` (20).
- Concurrency-sensitive SQL is tested against real PostgreSQL in an isolated schema. Lease-timing integration tests run in the `golang:1.25` container on the Docker VM clock (the Windows host clock drifts from the VM's).
- The owner merges PRs (`gh pr merge --merge`). Push and open the PR only after asking; never merge or tag.
- Docs never claim exactly-once execution or production readiness.

## Review Focus

1. **Panic after the response header was written:** the client sees a truncated response. The request must still be counted as a 5xx and the connection aborted. It must not be counted as the 200 that was already sent. (Task 2, `TestMiddlewareCountsPanicAfterHeaderAs5xx`.)
2. **Fan-in dependency without a stored context:** the dependency ran with tracing off, or before migration 8. Dispatch must skip it, store the remaining links, and not fail. (Task 4, `TestFanInDispatchSkipsDependenciesWithoutContextIntegration`.)
3. **The triggering dependency must not also be a link:** the parent context is never duplicated in `trace_links`. Compensations get no links. (Task 4, `TestFanInDispatchStoresSiblingTraceLinksIntegration`.)
4. **Retries of a fan-in step:** attempt 2 carries the same links as attempt 1, because they are stored on the job and not recomputed. (Task 5, `TestStartAttemptIncludesFanInTraceLinks`, attempt-2 case.)
5. **Probe traffic:** frequent `/healthz` and `/readyz` probes must not create root spans or dilute the availability SLI. They are still counted in `taskforge_http_requests_total`. (Task 2, `TestMiddlewareDoesNotTraceProbes`; Task 3, probe-dilution case.)
