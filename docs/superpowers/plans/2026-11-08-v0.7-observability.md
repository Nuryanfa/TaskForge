# v0.7.0 Observability Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make TaskForge observable: one trace per job that crosses API → PostgreSQL → worker → workflow steps, bounded Prometheus metrics, start-latency and reliability SLOs with tested burn-rate alerts, a provisioned Grafana dashboard, and a reproducible SLO burn demo.

**Architecture:** A W3C `traceparent` is stored on every job and workflow (migration 7) and read back by the worker, which starts one span per attempt (child, or new root + link for client-delayed jobs). The store only uses the OpenTelemetry *API* through a tiny `internal/tracectx` package; exporters, sampling, and Prometheus live in `internal/telemetry`. The store reports job outcomes and workflow settlements to an `Observer` **after commit**, so metrics never count rolled-back work.

**Tech Stack:** Go 1.25, pgx v5, OpenTelemetry Go (API, SDK, OTLP/HTTP exporter, `tracetest`), `prometheus/client_golang`, Prometheus + `promtool`, Grafana, Jaeger all-in-one, Docker Compose.

**Spec:** `docs/superpowers/specs/2026-11-08-v0.7-observability-design.md` (scope: **v0.7.0** per owner decision 12)

## Global Constraints

- Go module `github.com/Nuryanfa/TaskForge`; `go.mod` stays `go 1.25.0`. Pin the newest dependency releases whose `go` directive is ≤ 1.25 (check with `go mod tidy` leaving `go 1.25.0` untouched).
- New Go dependencies allowed: `go.opentelemetry.io/otel`, `.../otel/trace`, `.../otel/sdk`, `.../otel/exporters/otlp/otlptrace/otlptracehttp`, `.../otel/propagation`, `github.com/prometheus/client_golang`. No `otelhttp` contrib (ruling: a hand-written middleware gives the public-endpoint link rule and `unmatched` route label explicitly).
- `internal/store/postgres` may import only `internal/tracectx` and the OTel **API** (`otel`, `otel/trace`, `otel/propagation`); never the SDK or an exporter.
- Telemetry never fails or blocks work: no request or job may fail because tracing or metrics fail; export is asynchronous with a bounded queue (2048) and timeout (`TASKFORGE_OTEL_EXPORT_TIMEOUT`, default 5s).
- No payloads, results, idempotency keys, execution keys, DSNs, or NATS URLs in span attributes, metric labels, or logs. Job/workflow IDs only as span attributes.
- Metric labels: `kind` ∈ `job.RegisteredKinds` else `other`; `queue` ∈ `TASKFORGE_METRICS_QUEUES` (default `default`, ≤ 32 entries) else `other`; `route` = mux pattern or `unmatched`; `outcome` ∈ {`succeeded`,`retry_scheduled`,`dead_lettered`,`abandoned`}; `class` ∈ {`platform`,`handler`,`none`}.
- Platform failure codes: `LEASE_EXPIRED`, `SHUTDOWN_TIMEOUT`, `UNKNOWN_JOB_KIND`. Every other code is `handler`.
- Metrics listeners (loopback, separate from the API listener): API `127.0.0.1:9101`, worker `127.0.0.1:9102`, relay `127.0.0.1:9103`; env `TASKFORGE_METRICS_ADDR`, set-but-empty disables.
- `traceparent` regex: `^00-[0-9a-f]{32}-[0-9a-f]{16}-[0-9a-f]{2}$`. Only `tracecontext` propagation; no baggage or tracestate.
- Start-delay histogram buckets must include exactly `5` seconds. SLO targets: start latency 99 % ≤ 5 s; reliability 99.5 %; burn rates 14.4× (1h & 5m) and 6× (6h & 30m); minimum 20 valid events/hour.
- Every commit ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`; `gofmt -l .` empty and `go vet ./...` clean before each commit. Integration tests need `TASKFORGE_TEST_DATABASE_URL`; on Windows run `-race` in `golang:1.25` (see `docs/TESTING.md`).

## Review Focus

1. Sample ratio `0`: contexts still propagate (`traceparent` flags `00`), nothing is exported, jobs run normally. → Task 3 `TestSampledOutContextStillPropagates`.
2. A stored `traceparent` with all-zero trace or span ID (valid regex, invalid context) must be treated as absent, not crash or produce a broken parent. → Task 1 `TestSpanContextRejectsZeroIDs`.
3. An exporter endpoint that accepts connections but never responds must not stretch shutdown past the export timeout. → Task 3 `TestShutdownBoundedByHangingExporter`.
4. A metrics address that is already in use makes the process exit at startup with `metrics_listen_failed`, rather than running unobservable silently. → Task 4 `TestServeMetricsFailsOnBusyAddress`.
5. Idempotent replays (`200`) of jobs and workflows must not increment `taskforge_jobs_submitted_total`. → Task 6 `TestReplayDoesNotCountAsSubmission`.

**Interfaces:**
- Produces:

```go
type Observer interface {
    JobOutcome(kind, outcome, errorCode string)
    WorkflowSettled(status string)
}
func (s *Store) SetObserver(o Observer)          // nil-safe; default no-op
type Snapshot struct {
    Ready, Delayed, Running, ExpiredLease int64
```

Events are buffered per transaction and delivered only after `Commit` succeeds. Snapshot queries use indexed predicates only (`status='queued'`, `status='running'`, `published_at IS NULL`, `redriven_job_id IS NULL`, `workflows.status IN (...)`) and `NOW()`; ages are 0 when no row.
